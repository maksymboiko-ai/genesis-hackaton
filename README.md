# Mendly

Mendly створює персональний навчальний план за ціллю дитини, адаптує його за результатами тестів і може спиратися на завантажений PDF-підручник.

## 1. Як обрали ідею та зробили MVP

**Вибір ідеї.** В основі MVP — сценарій, у якому батьки описують навчальну ціль дитини, а план змінюється в міру навчання. **Доповнити командою:** [Які ідеї розглядали і чому обрали саме адаптивний план?]

1. Почали зі спільних API- та AI-контрактів і схеми даних. Frontend працював із моками, backend — із тестовою реалізацією AI-сервісу.
2. Зібрали основний сценарій від введення цілі до уроку й тесту. Додали оцінювання навичок і коригування плану за результатами.
3. Підключили PDF-підручники як джерело матеріалу для уроків, перевірили інтеграцію та порівняли моделі за якістю, затримкою й вартістю.

## 3. Архітектура, компроміси й витрати

- **Архітектура.** Next.js і TypeScript для вебінтерфейсу та API. Supabase для автентифікації, Postgres, пошуку фрагментів підручника через pgvector і зберігання PDF. Сервер викликає моделі через OpenRouter, а спільні контракти Zod задають формати API та відповідей моделей. [Архітектура](ARCHITECTURE.md) · [План backend](BACKEND_PLAN.md)
- **Компроміси.** Сервер оцінює відповіді й вирішує, коли коригувати план. Моделі генерують навчальний матеріал. Система генерує уроки в міру проходження, тож витрати на невідкриті уроки обмежені, але іноді учень чекає на готовий урок. [Архітектурні рішення](docs/adr/)
- **Витрати.** У тестовому сценарії з 8 уроками вибрана конфігурація коштувала орієнтовно **$0.036 на курс** за виклики моделей, приблизно на 65% менше за попередню. Дешевша модель для уроків давала оцінку **$0.019 на курс**, але генерувала урок у середньому за 12.8 с проти 3.8 с. **Доповнити командою:** [Фактичні витрати на хостинг, базу даних і зберігання.] [Звіт про оцінювання моделей](web/evals/REPORT.md)
